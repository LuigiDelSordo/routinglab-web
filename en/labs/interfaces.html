Interfaces and addressing

IP addresses, descriptions, no shutdown and loopback

Level: Beginner Time: 20 min Domain 1.0 Network Fundamentals

Scenario

R1 joins two networks: PC1's (192.168.1.0/24) on G0/0 and PC2's (192.168.2.0/24) on G0/1. The PCs already have their IP and default gateway, but the router is unconfigured and its interfaces ship shut down.

Assign the addresses from the table, add a description to each interface, bring them up and create Loopback0 with 10.0.0.1/32. Finally, check that the PCs can reach each other (from PC1's console: ping 192.168.2.10) and review the status with show ip interface brief.

Starting configuration

In the app this is already done. In Packet Tracer, before you start, enter each device with enable and configure terminal and type (or paste) these lines.

R1hostname R1 no ip domain-lookup

PCs and servers (Desktop › IP Configuration)

  • PC1: IP 192.168.1.10, mask 255.255.255.0, gateway 192.168.1.1
  • PC2: IP 192.168.2.10, mask 255.255.255.0, gateway 192.168.2.1

Tasks

What must end up working. In the app, each one ticks itself off as soon as you get it.

  1. G0/0 with 192.168.1.1/24 and a description
  2. G0/1 with 192.168.2.1/24 and a description
  3. Both interfaces up (up/up)
  4. Loopback0 with 10.0.0.1/32
  5. PC1 reaches PC2
  6. PC1 reaches Loopback0
  7. Checked with show ip interface brief
In Packet Tracer
  • Connect each PC straight to the router with a crossover cable (or the automatic one, the lightning bolt). The cable lights stay red until you issue no shutdown.
  • Each PC's IP is set in Desktop › IP Configuration.
Hints
  • G0/0 with 192.168.1.1/24 and a description: interface g0/0 → description LAN-PC1 → ip address 192.168.1.1 255.255.255.0
  • G0/1 with 192.168.2.1/24 and a description: interface g0/1 → description … → ip address 192.168.2.1 255.255.255.0
  • Both interfaces up (up/up): Router interfaces ship shut down: enter each one and type no shutdown
  • Loopback0 with 10.0.0.1/32: interface loopback 0 → ip address 10.0.0.1 255.255.255.255 (it's created when you enter it)
  • PC1 reaches PC2: If it fails, check the IP and state of both interfaces with show ip interface brief
  • PC1 reaches Loopback0: From PC1: ping 10.0.0.1
  • Checked with show ip interface brief: In privileged mode (or with do from config mode): show ip interface brief

Step-by-step solution

Try it on your own first: you learn much more by typing the commands yourself.

Show the solution

1Configure G0/0, PC1's LAN R1

Router interfaces ship shut down (administratively down): without no shutdown nothing happens, even if the IP is right.

R1enable configure terminal interface g0/0 description LAN-PC1 ip address 192.168.1.1 255.255.255.0 no shutdown

2Configure G0/1, PC2's LAN R1

Typing interface g0/1 inside another interface switches straight to the new one: no need to exit first.

R1interface g0/1 description LAN-PC2 ip address 192.168.2.1 255.255.255.0 no shutdown

3Create Loopback0 R1

A loopback is a logical interface that is always up. It's created when you enter it and usually takes a /32.

R1interface loopback 0 ip address 10.0.0.1 255.255.255.255 end

Verification

The three configured interfaces must show Status and Protocol up. "administratively down" means no shutdown is missing; "down/down" means there's no cable or the other end is off.

R1R1#show ip interface brief Interface IP-Address OK? Method Status Protocol GigabitEthernet0/0 192.168.1.1 YES manual up up GigabitEthernet0/1 192.168.2.1 YES manual up up GigabitEthernet0/2 unassigned YES unset administratively down down Loopback0 10.0.0.1 YES manual up up

The first echo may be lost while the router resolves the MAC through ARP; the rest reply with TTL=127 (128 minus the router hop).

Common mistakes

  • Typing the IP with a /24 mask: IOS only accepts the full mask (255.255.255.0).
  • Putting the same network on two interfaces: IOS rejects it with "% … overlaps with …".
