Servidor DHCP en el router

Direcciones excluidas, pool, puerta de enlace y DNS

Nivel: Básico Tiempo: 20 min Dominio 4.0 Servicios IP

Escenario

Los PC de la LAN 192.168.1.0/24 están configurados para pedir su IP por DHCP, pero nadie les contesta. R1 hará de servidor.

Reserva las direcciones 192.168.1.1 a 192.168.1.10 para equipos con IP fija y crea un pool llamado LAN que reparta el resto, con 192.168.1.1 como puerta de enlace y 8.8.8.8 como DNS.

Ojo: si un PC recibe su IP antes de que termines el pool, se quedará sin puerta de enlace o DNS. En su consola, ipconfig /renew la pide de nuevo.

Configuración de partida

En la app esto viene hecho. En Packet Tracer, antes de empezar, entra en cada equipo con enable y configure terminal y escribe (o pega) estas líneas.

R1hostname R1 no ip domain-lookup interface g0/0 ip address 192.168.1.1 255.255.255.0 no shutdown
SW1hostname SW1 no ip domain-lookup

PC y servidores (Desktop › IP Configuration)

  • PC1: DHCP
  • PC2: DHCP

Tareas

Lo que tiene que quedar funcionando. En la app, cada una se marca sola en cuanto la consigues.

  1. Excluidas 192.168.1.1 a 192.168.1.10
  2. Pool LAN con la red 192.168.1.0/24
  3. El pool reparte 192.168.1.1 como puerta de enlace
  4. El pool reparte 8.8.8.8 como DNS
  5. PC1 y PC2 reciben IP, puerta de enlace y DNS
  6. Comprobado con show ip dhcp binding
En Packet Tracer
  • En cada PC, ve a Desktop › IP Configuration y elige DHCP. También puedes usar ipconfig /renew en Command Prompt.
Pistas
  • Excluidas 192.168.1.1 a 192.168.1.10: ip dhcp excluded-address 192.168.1.1 192.168.1.10 (en configuración global, no dentro del pool)
  • Pool LAN con la red 192.168.1.0/24: ip dhcp pool LAN → network 192.168.1.0 255.255.255.0
  • El pool reparte 192.168.1.1 como puerta de enlace: Dentro del pool: default-router 192.168.1.1
  • El pool reparte 8.8.8.8 como DNS: Dentro del pool: dns-server 8.8.8.8
  • PC1 y PC2 reciben IP, puerta de enlace y DNS: Mira su configuración con ipconfig /all. Si les falta algo, ipconfig /renew.
  • Comprobado con show ip dhcp binding: show ip dhcp binding en R1

Solución paso a paso

Inténtalo antes por tu cuenta: se aprende mucho más escribiendo los comandos tú.

Ver la solución

1Reserva las direcciones fijas R1

Las excluidas se configuran fuera del pool, en modo global. Aquí quedan para el router y otros equipos con IP fija.

R1enable configure terminal ip dhcp excluded-address 192.168.1.1 192.168.1.10

2Crea el pool R1

network define qué se reparte; default-router y dns-server, lo que recibe cada PC además de la IP.

R1ip dhcp pool LAN network 192.168.1.0 255.255.255.0 default-router 192.168.1.1 dns-server 8.8.8.8 end

3Pide la IP en los PC PC1

Si un PC pidió la IP antes de terminar el pool, se quedará sin puerta de enlace o DNS hasta que la pida de nuevo.

PC1ipconfig /renew

4Y en PC2 PC2

PC2ipconfig /renew

Verificación

Cada concesión liga una IP (desde la .11) a la MAC del PC.

R1R1#show ip dhcp binding IP address Client-ID/ Lease expiration Type Hardware address 192.168.1.11 00D0.AF38.7A1A -- Automatic 192.168.1.12 0001.30DB.97A9 -- Automatic

El PC muestra su IP, la puerta de enlace, el servidor DHCP y el DNS que le ha dado el router.

PC1C:\>ipconfig /all FastEthernet0 Connection:(default port) Connection-specific DNS Suffix..: Physical Address................: 00D0.AF38.7A1A Link-local IPv6 Address.........: FE80::2D0:AFFF:FE38:7A1A IPv6 Address....................: :: IPv4 Address....................: 192.168.1.11 Subnet Mask.....................: 255.255.255.0 Default Gateway.................: :: 192.168.1.1 DHCP Servers....................: 192.168.1.1 DNS Servers.....................: :: 8.8.8.8

Errores típicos

  • Poner excluded-address dentro del pool: no existe ahí, va en configuración global.
  • Olvidar default-router: los PC reciben IP pero no salen de su red.
