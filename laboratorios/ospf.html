OSPF de área única

router-id, network con wildcard, interfaces pasivas y vecinos

Nivel: Intermedio Tiempo: 35 min Dominio 3.0 Conectividad IP

Escenario

Tres routers en fila: R1 – R2 – R3. R2 ya tiene OSPF (proceso 1, router-id 2.2.2.2). Te toca configurar R1 y R3 para que las LAN de los extremos se vean sin escribir ni una ruta estática.

Usa el proceso 1 y el área 0. Fija el router-id (1.1.1.1 en R1 y 3.3.3.3 en R3) antes de anunciar las redes, anuncia todas sus redes conectadas y pon como pasiva la interfaz de la LAN, donde no hay ningún router con quien hablar. Verifica los vecinos con show ip ospf neighbor.

Configuración de partida

En la app esto viene hecho. En Packet Tracer, antes de empezar, entra en cada equipo con enable y configure terminal y escribe (o pega) estas líneas.

R1hostname R1 no ip domain-lookup interface g0/0 ip address 192.168.1.1 255.255.255.0 no shutdown interface g0/1 ip address 10.0.12.1 255.255.255.252 no shutdown
R2hostname R2 no ip domain-lookup interface g0/0 ip address 10.0.12.2 255.255.255.252 no shutdown interface g0/1 ip address 10.0.23.1 255.255.255.252 no shutdown router ospf 1 router-id 2.2.2.2 network 10.0.12.0 0.0.0.3 area 0 network 10.0.23.0 0.0.0.3 area 0
R3hostname R3 no ip domain-lookup interface g0/0 ip address 10.0.23.2 255.255.255.252 no shutdown interface g0/1 ip address 192.168.3.1 255.255.255.0 no shutdown

PC y servidores (Desktop › IP Configuration)

  • PC1: IP 192.168.1.10, máscara 255.255.255.0, puerta de enlace 192.168.1.1
  • PC3: IP 192.168.3.10, máscara 255.255.255.0, puerta de enlace 192.168.3.1

Tareas

Lo que tiene que quedar funcionando. En la app, cada una se marca sola en cuanto la consigues.

  1. R1: OSPF 1 con router-id 1.1.1.1
  2. R1 anuncia sus dos redes en el área 0
  3. R1: G0/0 pasiva
  4. R3: router-id 3.3.3.3 y sus dos redes
  5. R3: G0/1 pasiva
  6. R2 tiene a R1 y R3 como vecinos FULL
  7. PC1 llega a PC3
  8. Comprobado con show ip ospf neighbor
En Packet Tracer
  • Los routers se unen con cable cruzado y cada PC a su router, también con cruzado.
  • Haz la configuración de partida de los tres routers. R2 ya trae su OSPF en ella.
Pistas
  • R1: OSPF 1 con router-id 1.1.1.1: router ospf 1 → router-id 1.1.1.1. Si ya tenía vecinos, IOS pide clear ip ospf process.
  • R1 anuncia sus dos redes en el área 0: network 192.168.1.0 0.0.0.255 area 0 y network 10.0.12.0 0.0.0.3 area 0 (la wildcard es la máscara invertida)
  • R1: G0/0 pasiva: passive-interface g0/0 dentro de router ospf 1
  • R3: router-id 3.3.3.3 y sus dos redes: Igual que en R1, con 10.0.23.0 0.0.0.3 y 192.168.3.0 0.0.0.255
  • R3: G0/1 pasiva: passive-interface g0/1
  • R2 tiene a R1 y R3 como vecinos FULL: Los vecinos necesitan misma área, misma subred y que la interfaz no sea pasiva
  • PC1 llega a PC3: Desde PC1: ping 192.168.3.10
  • Comprobado con show ip ospf neighbor: show ip ospf neighbor en R1 o R3

Solución paso a paso

Inténtalo antes por tu cuenta: se aprende mucho más escribiendo los comandos tú.

Ver la solución

1Arranca OSPF y fija el router ID R1

El router ID se elige al arrancar el proceso. Si lo cambias cuando ya hay vecinos, IOS pide clear ip ospf process para aplicarlo.

R1enable configure terminal router ospf 1 router-id 1.1.1.1

2Anuncia las redes R1

network usa wildcard (la máscara invertida) y activa OSPF en las interfaces cuya IP encaja.

R1network 192.168.1.0 0.0.0.255 area 0 network 10.0.12.0 0.0.0.3 area 0

3Haz pasiva la interfaz de la LAN R1

Una interfaz pasiva se sigue anunciando, pero no envía hellos: en la LAN no hay routers con quien hablar.

R1passive-interface g0/0 end

4Haz lo mismo en R3 R3

R3enable configure terminal router ospf 1 router-id 3.3.3.3 network 10.0.23.0 0.0.0.3 area 0 network 192.168.3.0 0.0.0.255 area 0 passive-interface g0/1 end

Verificación

R2 tiene a 1.1.1.1 y 3.3.3.3 en estado FULL. En un enlace Ethernet uno será DR y el otro BDR.

R2R2#show ip ospf neighbor Neighbor ID Pri State Dead Time Address Interface 3.3.3.3 1 FULL/DR 00:00:37 10.0.23.2 GigabitEthernet0/1 1.1.1.1 1 FULL/BDR 00:00:39 10.0.12.1 GigabitEthernet0/0

R1 aprende por OSPF (O) la red de R3 y el enlace entre R2 y R3, con distancia 110.

R1R1#show ip route ospf Codes: L - local, C - connected, S - static, R - RIP, M - mobile, B - BGP D - EIGRP, EX - EIGRP external, O - OSPF, IA - OSPF inter area N1 - OSPF NSSA external type 1, N2 - OSPF NSSA external type 2 E1 - OSPF external type 1, E2 - OSPF external type 2, E - EGP i - IS-IS, L1 - IS-IS level-1, L2 - IS-IS level-2, ia - IS-IS inter area * - candidate default, U - per-user static route, o - ODR P - periodic downloaded static route Gateway of last resort is not set 10.0.0.0/30 is subnetted, 1 subnets O 10.0.23.0/30 [110/2] via 10.0.12.2, 00:00:12, GigabitEthernet0/1 O 192.168.3.0/24 [110/3] via 10.0.12.2, 00:00:12, GigabitEthernet0/1

Llegar de un extremo a otro sin ninguna ruta estática es la prueba final.

Errores típicos

  • Escribir la máscara en lugar de la wildcard en network (255.255.255.0 en vez de 0.0.0.255).
  • Áreas distintas a cada lado del enlace: los routers no llegan a ser vecinos.
  • Poner pasiva la interfaz hacia otro router: se anuncia, pero no se forma la vecindad.
