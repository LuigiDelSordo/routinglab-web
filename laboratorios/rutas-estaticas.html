Rutas estáticas, por defecto y flotantes

ip route, ruta por defecto y una de respaldo con distancia administrativa

Nivel: Intermedio Tiempo: 25 min Dominio 3.0 Conectividad IP

Escenario

R1 es el router de una sucursal y R2 el de la central, que además da salida a Internet (su Loopback0, 203.0.113.1). Están unidos por dos enlaces: el principal (G0/1, 10.0.0.0/30) y uno de respaldo (G0/2, 10.0.0.4/30).

En R1, crea una ruta por defecto por 10.0.0.2 y otra de respaldo por 10.0.0.6 con distancia administrativa 5, para que solo se use si cae el enlace principal. En R2, crea una ruta estática hacia la LAN de la sucursal (192.168.1.0/24) por 10.0.0.1. Comprueba la tabla con show ip route.

Configuración de partida

En la app esto viene hecho. En Packet Tracer, antes de empezar, entra en cada equipo con enable y configure terminal y escribe (o pega) estas líneas.

R1hostname R1 no ip domain-lookup interface g0/0 ip address 192.168.1.1 255.255.255.0 no shutdown interface g0/1 description Principal ip address 10.0.0.1 255.255.255.252 no shutdown interface g0/2 description Respaldo ip address 10.0.0.5 255.255.255.252 no shutdown
R2hostname R2 no ip domain-lookup interface g0/0 ip address 10.0.0.2 255.255.255.252 no shutdown interface g0/1 ip address 192.168.2.1 255.255.255.0 no shutdown interface g0/2 ip address 10.0.0.6 255.255.255.252 no shutdown interface loopback 0 description Internet ip address 203.0.113.1 255.255.255.255

PC y servidores (Desktop › IP Configuration)

  • PC1: IP 192.168.1.10, máscara 255.255.255.0, puerta de enlace 192.168.1.1
  • PC2: IP 192.168.2.10, máscara 255.255.255.0, puerta de enlace 192.168.2.1

Tareas

Lo que tiene que quedar funcionando. En la app, cada una se marca sola en cuanto la consigues.

  1. R1: ruta por defecto por 10.0.0.2
  2. R1: ruta flotante por 10.0.0.6 con distancia 5
  3. R2: ruta a 192.168.1.0/24 por 10.0.0.1
  4. PC1 llega a PC2
  5. PC1 llega a Internet (203.0.113.1)
  6. El tráfico usa el enlace principal; el de respaldo espera
  7. Comprobado con show ip route en R1
En Packet Tracer
  • R1 y R2 se unen con dos cables cruzados: G0/1 con G0/0 (principal) y G0/2 con G0/2 (respaldo).
Pistas
  • R1: ruta por defecto por 10.0.0.2: ip route 0.0.0.0 0.0.0.0 10.0.0.2
  • R1: ruta flotante por 10.0.0.6 con distancia 5: ip route 0.0.0.0 0.0.0.0 10.0.0.6 5. El 5 es la distancia administrativa: más alta que la estática normal (1).
  • R2: ruta a 192.168.1.0/24 por 10.0.0.1: ip route 192.168.1.0 255.255.255.0 10.0.0.1
  • PC1 llega a PC2: Hace falta ruta de ida (R1) y de vuelta (R2)
  • PC1 llega a Internet (203.0.113.1): Desde PC1: ping 203.0.113.1
  • El tráfico usa el enlace principal; el de respaldo espera: En show ip route de R1 solo debe salir S* por 10.0.0.2. Si apagas G0/1, aparecerá la ruta por 10.0.0.6.
  • Comprobado con show ip route en R1: show ip route

Solución paso a paso

Inténtalo antes por tu cuenta: se aprende mucho más escribiendo los comandos tú.

Ver la solución

1Ruta por defecto principal R1

0.0.0.0 0.0.0.0 encaja con cualquier destino: es lo que usa R1 cuando no tiene una ruta más concreta.

R1enable configure terminal ip route 0.0.0.0 0.0.0.0 10.0.0.2

2Ruta flotante de respaldo R1

El 5 final es la distancia administrativa. Como es peor que la de la principal (1), solo entra en la tabla si la principal desaparece.

R1ip route 0.0.0.0 0.0.0.0 10.0.0.6 5 end

3Ruta de vuelta hacia la sucursal R2

Sin ella, los paquetes llegan a R2 pero las respuestas no saben volver a 192.168.1.0/24.

R2enable configure terminal ip route 192.168.1.0 255.255.255.0 10.0.0.1 end

Verificación

Solo aparece S* por 10.0.0.2: la flotante está configurada pero espera. Apaga G0/1 y vuelve a mirar: entrará la ruta por 10.0.0.6.

El primer salto es R1 y el segundo, la loopback de R2.

PC1C:\>tracert 203.0.113.1 Tracing route to 203.0.113.1 over a maximum of 30 hops: 1 0 ms 0 ms 0 ms 192.168.1.1 2 0 ms 0 ms 0 ms 203.0.113.1 Trace complete.

Errores típicos

  • Configurar solo la ida: los ping fallan porque R2 no tiene ruta de vuelta.
  • Dar a la flotante la misma distancia que a la principal: el router reparte la carga entre las dos en lugar de usarla de respaldo.
